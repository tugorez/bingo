# Bingo 🐶

*"You found it!"*

A friendly, component-based framework for Flutter that brings the power of true dependency injection and declarative, scalable architecture.

---

## What is Bingo?

Bingo is an opinionated framework for building Flutter applications, heavily inspired by modern web frameworks like Angular.

It uses **code generation** (`build_runner`) to connect your services, controllers, and components, allowing you to write clean, testable, and scalable Flutter apps with minimal boilerplate.

-   **True Dependency Injection:** Build your app from injectable services, providers, and controllers.
-   **Component-Based:** Create features as self-contained `Component` widgets.
-   **Clear Separation of Concerns:** Enforces a clean split between your **State**, your **Controller** (logic), and your **Component** (UI).
-   **Minimal Boilerplate:** The generator writes all the "glue" code for you.

## Core Concepts

Bingo's architecture is built on a few core concepts:

-   **`@Module`**: A class that groups providers and components into a single, importable feature area.
-   **`@Injectable`**: Marks a class (like `LoggerService` or `UserRepository`) for automatic dependency injection.
-   **`@Controller`**: The "brain" of your feature. This class extends `Controller<T>` and manages the business logic and immutable state `T`.
-   **`@Component`**: An annotation that marks a Flutter `Widget` as a component. The framework will automatically find its `Controller` and provide its `State` and `Commands` as constructor arguments.
-   **`@command`**: An annotation that cleanly exposes a method from a `Controller` to its `Component` via a generated `Commands` interface.

## Installation

1.  Add `bingo` to your `dependencies` and `build_runner` to your `dev_dependencies`.

    ```yaml
    # pubspec.yaml
    dependencies:
      flutter:
        sdk: flutter
      bingo: ^0.1.0 # (Or use path: for local dev)
      provider: ^6.1.2

    dev_dependencies:
      flutter_test:
        sdk: flutter
      build_runner: ^2.4.0
      # We will need a builder package, e.g., bingo_builder
      # bingo_builder: ^0.1.0 
    ```

2.  Run `flutter pub get`.

## Quick Example: The Counter App

Here is what a complete "counter" feature looks like with Bingo.

### 1. The State (`counter_state.dart`)
A plain, immutable data class.

```dart
import 'package:flutter/foundation.dart';

@immutable
class CounterState {
  final int count;
  const CounterState({required this.count});
  
  static CounterState get initial => const CounterState(count: 0);

  CounterState copyWith({int? count}) {
    return CounterState(count: count ?? this.count);
  }

  // Value-equality is required!
  @override
  bool operator ==(Object other) => other is CounterState && other.count == count;
  @override
  int get hashCode => count.hashCode;
}
```
### 2. The Controller (`counter_controller.dart`)
The business logic. It gets dependencies (like LoggerService) injected automatically.

```dart
import 'package:bingo/bingo.dart';
import 'package:my_app/logger_service.dart';
import 'package:my_app/counter/counter_state.dart';

@Injectable()
class CounterController extends Controller<CounterState> {
  final LoggerService _logger;

  // The injector provides LoggerService automatically
  CounterController(this._logger) : super(CounterState.initial);

  @command
  void increment() {
    _logger.log('Incrementing count...');
    state = state.copyWith(count: state.count + 1);
  }

  @command
  void reset() {
    _logger.log('Resetting count.');
    state = CounterState.initial;
  }
}
```
### 3. The Component (`counter_component.dart`)
The Widget that defines the UI. It receives model and commands from the framework.

```dart
import 'package:flutter/material.dart';
import 'package:bingo/bingo.dart';
import 'package:my_app/counter/counter_controller.dart';
import 'package:my_app/counter/counter_state.dart';

// This file will be generated by Bingo
import 'package:my_app/counter/counter_controller.commands.g.dart'; 

@Component(
  controller: CounterController,
)
class CounterComponent extends StatelessWidget {
  // These are injected by the Bingo's generated binding widget
  final CounterState model;
  final CounterCommands commands;

  const CounterComponent({
    super.key,
    required this.model,
    required this.commands,
  });

  @override
  Widget build(BuildContext context) {
    return Column(
      mainAxisAlignment: MainAxisAlignment.center,
      children: [
        Text('Count: ${model.count}'),
        ElevatedButton(
          onPressed: commands.increment,
          child: const Text('Increment'),
        ),
      ],
    );
  }
}
```
### 4. The Module (`counter_module.dart`)
The "glue" that tells the DI container about this feature.

```dart
import 'package:bingo/bingo.dart';
import 'package:my_app/counter/counter_component.dart';
import 'package:my_app/counter/counter_controller.dart';

@Module(
  providers: [
    CounterController,
  ],
  components: [
    CounterComponent,
  ],
)
class CounterModule {}
```
### 5. The App (`app_module.dart` & `main.dart`)
Finally, import your feature module into your main AppModule.

```dart
// lib/app_module.dart
import 'package:bingo/bingo.dart';
import 'package:my_app/counter/counter_module.dart';
import 'package:my_app/logger_service.dart';

@Module(
  imports: [
    CounterModule, // <-- Import your feature module
  ],
  providers: [
    LoggerService, // Global services
  ],
)
class AppModule {}
```

## Code Generation
To run the generator and build the injectors, run:

```bash
flutter pub run build_runner build --delete-conflicting-outputs
```
Or for development:

```bash
flutter pub run build_runner watch --delete-conflicting-outputs
```
